# 05 성능 엔지니어링 / 01 인덱스

인덱스가 어떻게 풀스캔을 트리 탐색으로 바꾸는지, 그리고 인덱스가 만능이 아닌 이유를 employees의 대용량 데이터로 확인한다. 03.02·03.03·04.02가 예고한 "느림의 처방 = 인덱스"의 본론이다.

## What you will learn

- B-tree 인덱스 원리: 풀스캔 O(n) → 트리 탐색 O(log n)
- InnoDB 클러스터드/세컨더리 인덱스와 북마크 룩업 → 커버링 인덱스의 근거
- 인덱스 유형(단일·복합·커버링)과 복합 인덱스 최좌선 접두사 규칙
- 인덱스 전후 실행 시간 비교(약 0.9초 → 0.01초)와 **선택도(selectivity)**: 넓은 범위는 인덱스가 있어도 풀스캔
- `ORDER BY ... LIMIT` 정렬 제거, `Using index` 커버링, 인덱스의 쓰기 비용
- 최좌선 규칙은 기존 PK `(emp_no, from_date)`로 시연 (EXPLAIN 심층 해석은 실행 계획에서)
- **lab01** 단일 인덱스와 선택도 / **lab02** 정렬과 커버링 인덱스 / **lab03** 복합 인덱스와 최좌선 규칙

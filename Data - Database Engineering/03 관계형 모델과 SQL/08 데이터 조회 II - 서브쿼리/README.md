# 03 관계형 모델과 SQL / 08 데이터 조회 II: 서브쿼리 (Subquery)

다른 쿼리의 결과가 먼저 있어야 물을 수 있는 질문에 서브쿼리를 쓴다. 조회 II(집계 → 조인 → 서브쿼리)의 마지막이자 Ch03 SQL 다이제스트를 닫는 절이다. 집계에서 미뤄 둔 "집계의 집계"를 여기서 푼다.

## What you will learn

- 서브쿼리의 필요성: 두 쿼리로 나눠 풀 때의 값 옮기기와 **두 쿼리 사이 데이터 변경** 문제를 한 문장으로 없앤다
- 서브쿼리가 놓이는 자리: `WHERE`절(비교 기준, 값 하나면 `=` 여럿이면 `IN`), `FROM`절(파생 테이블, **별칭 필수**), `SELECT`절(행마다 값)
- 집계의 "집계의 집계"(`MAX(AVG())`)를 `FROM`절 서브쿼리로 해결 (06 집계 hook 회수)
- 쓰기 DML의 서브쿼리: **서비스 트랜잭션의 쓰기는 짧고 원자적이어야** 해 지양, 서브쿼리를 낀 쓰기는 대개 배치/벌크 (병행제어 주의 대상)

## Labs

- **lab01 위치에 따른 서브쿼리** (employees): `WHERE`절(전사 평균 이상 급여자, 비교 기준 계산) / `FROM`절(사원별 평균 중 최고, 파생 테이블 `AS t` 별칭 필수 — 06 `MAX(AVG())` 막힘의 해결)

## Hooks (앞에서 받음 / 뒤로 이어짐)

- 06 집계의 "집계의 집계는 서브쿼리로" → lab01 FROM절에서 회수

- 파생 테이블의 처리(materialize, EXPLAIN의 DERIVED) → 인덱스와 실행 계획(Ch05)
